<form-multi-switch>

Present a native radio group as a segmented control without replacing its inputs. See the README for installation and API documentation.

Keyboard too: Use Tab to reach a group, arrow keys to change its selection, and Space to select.

Plays well with native form behavior

Connect a behavior module

If your switch needs JavaScript to do its job, point the script attribute at that module. The component loads it and calls its initialize() function, passing in the switch and an AbortSignal you can use to clean up event listeners. Your radios keep their usual appearance until the module is ready.

Example: Switch between a list and a grid

This script reads the selected value and changes how the saved reports are displayed. You don’t need a separate <script> element to load it. 

<form-multi-switch script="./view-behavior.js">
  <fieldset>
    <legend>Saved reports view</legend>
    <label><input type="radio" name="reports-view"
      value="list" checked>List</label>
    <label><input type="radio" name="reports-view"
      value="grid">Grid</label>
  </fieldset>
</form-multi-switch>
<ul data-view-preview>
  <li>Weekly sales</li>
  <li>Stock levels</li>
  <li>Returns</li>
  <li>Customer feedback</li>
</ul>

// view-behavior.js:
export function initialize(control, { signal }) {
  const preview = control.parentElement
    .querySelector('[data-view-preview]');
  const update = () => {
    preview.dataset.view = control.value;
  };
  control.addEventListener('form-multi-switch:change',
    update, { signal });
  update();
  return () => preview.removeAttribute('data-view');
}

[data-view-preview][data-view='grid'] {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 0.5rem;
}

Adjust the spacing of a preview

Comfortable and compact report spacing

Use the selected value to change the report list’s line height. The radios remain ordinary controls while the module loads, and the list keeps its original spacing if setup fails or the control disconnects. 

<form-multi-switch script="./density-behavior.js">
  <fieldset>
    <legend>Preview spacing</legend>
    <label><input type="radio" name="preview-density"
      value="comfortable" checked>Comfortable</label>
    <label><input type="radio" name="preview-density"
      value="compact">Compact</label>
  </fieldset>
</form-multi-switch>
<ul data-preview>
  <li>First saved report</li>
  <li>Second saved report</li>
  <li>Third saved report</li>
</ul>

// Your behavior module:
export function initialize(control, { signal }) {
  const preview = control.parentElement
    .querySelector('[data-preview]');
  const original = preview.style.lineHeight;
  const update = () => {
    preview.style.lineHeight =
      control.value === 'compact' ? '1.2' : '2.4';
  };
  control.addEventListener('form-multi-switch:change',
    update, { signal });
  update();
  return () => { preview.style.lineHeight = original; };
}

Recover when a behavior cannot load

If a module cannot load or its initializer rejects, authored radios keep their native appearance and behavior. The component rejects ready and fires form-multi-switch:error; your application supplies any visible, translated error message.

Fix the module URL or initializer, then call refresh() to retry. Remove script to enhance the radios without that behavior. Refresh reruns setup, but doesn’t bypass the browser’s module cache or cancel an in-flight import. Read the new ready promise after each attempt. See the behavior module reference for cancellation, cleanup, CSP, and CORS requirements.

Observe a view selection

      value="grid">Grid</label>
  </fieldset>

<pre id="event-log" role="log" aria-live="polite">
Select a view to inspect its events.</pre>

const control = document.querySelector('#event-view');
const output = document.querySelector('#event-log');
const entries = [];
for (const name of ['activate', 'change']) {
  control.addEventListener(`form-multi-switch:${name}`, (event) => {
    entries.unshift(`${name} ${JSON.stringify(event.detail)}`);
    entries.length = Math.min(entries.length, 6);
    output.textContent = entries.join('\n');
  });
}

Customize the keyboard focus ring

Set --multi-switch-outline for the whole focus ring and --multi-switch-outline-offset for its distance from the segment. The radio keeps focus; the component draws the ring on its label when the radio matches :focus-visible. No extra label selector or tab stop is needed.

These properties work with wrapping and separate labels, including in forced colors. You can share a custom property with your site’s focus rule, as shown here. Use Tab to reach the group and arrow keys to change its selection.

For a browser-styled ring, set --multi-switch-outline: auto CanvasText. Browsers may use their own painted color for an auto ring, so check its rendered contrast. 

<form-multi-switch class="custom-focus">
  <fieldset>
    <legend>Result order</legend>
    <label><input type="radio" name="result-order"
      value="recommended" checked>Recommended</label>
    <label><input type="radio" name="result-order"
      value="newest">Newest</label>
    <label><input type="radio" name="result-order"
      value="oldest">Oldest</label>
  </fieldset>
</form-multi-switch>

.custom-focus {
  --demo-focus-ring: 4px dashed CanvasText;
  --multi-switch-outline: var(--demo-focus-ring);
  --multi-switch-outline-offset: 4px;
