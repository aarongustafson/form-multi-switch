<form-multi-switch>

Present a native radio group as a segmented control without replacing its inputs. See the README for installation and API documentation.

Try it: Use Tab to reach a group, arrow keys to change its selection, and Space to select.

Enhance your existing radios

Three delivery choices

All three choices are available. Submit the form to inspect the selected value, or reset it to restore Standard. This example uses the default styling, including a shared border around every choice. 

<form-multi-switch>
  <fieldset>
    <legend>Delivery speed</legend>
    <label><input type="radio" name="delivery"
      value="standard" checked>Standard</label>
    <label><input type="radio" name="delivery"
      value="express">Express</label>
    <label><input type="radio" name="delivery"
      value="overnight">Overnight</label>
  </fieldset>
</form-multi-switch>

Shoe sizes in a wrapping list

Use your own grid for a longer list. Each size has its own border and rounded corners rather than pretending the wrapped rows form one continuous switch. A diagonal line marks size 8.5 as unavailable; its label also includes that word for screen-reader users. 

<form-multi-switch class="size-grid">
  <fieldset>
    <legend>Shoe size (US women’s)</legend>
    <ul>
      <li><label><input type="radio" name="shoe-size"
        value="6">6</label></li>
      <li><label><input type="radio" name="shoe-size"
        value="8.5" disabled>8.5
        <span class="visually-hidden"> (unavailable)</span>
      </label></li>
      <!-- Repeat for the available sizes. -->
    </ul>
  </fieldset>
</form-multi-switch>

Configure the choices

Generate a group from attributes

Supply a name, legend text, and JSON choices to generate the native controls. This mode needs JavaScript to create the inputs. 

<form-multi-switch
  name="billing"
  label="Billing frequency"
  choices='[
    {"label":"Monthly","value":"monthly"},
    {"label":"Quarterly","value":"quarterly"},
    {"label":"Annually","value":"annual"}
  ]'
  value="quarterly"
></form-multi-switch>

Generate a group from application data

Use configure() when your choices come from JavaScript. The button changes the current selection without changing the reset default or firing an interaction event. 

<form-multi-switch id="js-density">
</form-multi-switch>

const control = document.querySelector('#js-density');
control.configure({
  name: 'density',
  label: 'Display density',
  choices: [
    { label: 'Comfortable', value: 'comfortable' },
    { label: 'Compact', value: 'compact' },
    { label: 'Condensed', value: 'condensed' }
  ],
  value: 'comfortable'
});

control.value = 'compact';

Restyle the same native control

Use custom properties for colors, padding, and corners. Use the light-DOM hooks when you want to change individual states. These examples change the presentation, not the radio behavior.

Resize the page to try the narrow layout. Below 20rem of available component width, choices stack as one connected control instead of wrapping into partial rows. First and last corners follow the new layout.

Use your colors and a pill outline

Set one border color for the whole group, independent of the selected text color. Increase the radius to round the outer ends.

Use icons without losing the labels

System, light, and dark choices

Keep a text label for every radio and add decorative CSS masks. icon-only visually hides the text after enhancement; assistive technology can still name each choice. This example only selects a value—it doesn’t change the page theme. 

<form-multi-switch class="icons pill"
  name="appearance" label="Appearance preview"
  choices='[
    {"label":"System","value":"system"},
    {"label":"Light","value":"light"},
    {"label":"Dark","value":"dark"}

  value="system" icon-only
></form-multi-switch>

// Your behavior module:
export function initialize(control, { signal }) {
  const preview = control.closest('section')
    .querySelector('[data-preview]');
  const updatePreview = () => {
    preview.style.lineHeight =
      control.value === 'compact' ? '1.2' : '2.4';
  };
  control.addEventListener('form-multi-switch-change',
    updatePreview, { signal });
  updatePreview();
}

Keep the fallback if behavior fails

A deliberately rejected initializer

This module intentionally rejects initialization. The radios keep their ordinary presentation, and the error appears below and in the console.

    <label><input type="radio" name="page-size"

Inspect interaction events

Separate activation from a value change

Click a selected choice again to see activation without another change. Arrow-key selection still produces change events. The log shows the latest six events from the examples above. 

document.addEventListener(
  'form-multi-switch-change',
  (event) => {
    const { value, previousValue, index } = event.detail;
    console.log(value, previousValue, index);
  }
);

document.addEventListener(
  'form-multi-switch-activate',
  (event) => console.log(event.detail)
);
